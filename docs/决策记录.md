## 0001 · 2026-10-28 · 仓库根移到 `本体\`，Git 只管代码

**背景**

汐的东西分在 `人格\`、`记忆\`、`本体\`。原先 `本体\dsh-xi-repo` 是个仓库副本，真正在跑的却是
`本体\dsh-xi` 和 `本体\xi-qq`——两份代码，8 个文件（0.7.1 人格/记忆分家）和 5 个调试脚本只在跑的那份里。
那时 `git checkout` 退的是仓库，跑的不动，等于没存档。

**决定**

1. 仓库根 = `E:\Ai-Agent\汐\本体`。`dsh-xi\`、`xi-qq\` 直接在根下，仓库里就是正在跑的代码。
2. 一次功能一个 commit，验证过再提交；发版打 tag（从 `v0.7.1` 起）。
3. 拉取只用 `git pull --ff-only`。合不了就停，先问，**不自动 merge**。
4. 图片、音频、视频不进 Git；`qq\`、`日志\`、`node_modules`、`_备份` 也不进。
5. 插件加载路径不变：`~/.dsh/plugins/dsh-xi` → `本体\dsh-xi`，`~/.dsh/xi-qq` → `本体\qq`。

**代价**

- `dsh-xi-qq/` 改名成 `xi-qq/`，这个 commit 里同时有移动和功能改动，早期 diff 要靠 `git log -M` 才看清。
- 拉取不再"自动合并"，冲突得人看一眼——这是故意的，自动 merge 会合出「干净但一跑就挂」的结果。
- `*.png` 一律忽略，以后界面要用的图得放 `素材\` 或改成 SVG。

**怎么退**

| 场景 | 命令 | 之后 |
|---|---|---|
| 退回某个版本 | `git switch --detach v0.7.0` | 重启 DSH，刷新页面 |
| 撤销最近一次提交，改动留在工作区 | `git reset --soft HEAD~1` | 不用重启，代码没变 |
| 撤销某次提交但留历史 | `git revert <sha>` | 重启 DSH |
| 对齐远端最新 | `git fetch origin && git reset --hard origin/main` | 重启 DSH（本地改动先 commit 或 stash） |

重启 = 关掉 DSH 再打开（`DeepSeek Harness.exe`），不是只刷新页面：`lib\*.js` 由宿主进程加载，
`client.js` 由页面加载，两边都要重来。

**新功能怎么走**

`git switch -c feat/xxx` → 改 → 重启验证 → 让阿晚确认 → `git switch main && git merge --ff-only feat/xxx` → 打 tag → 推。

## 0002 · 2026-10-28 · 群聊近况用 agent 作用域挂进提示词（抄 SurfCore 的第一件）

**背景**

原来只看得到点名她的那一句，加 6 行摘要。SurfCore 那套「模型自己看消息、自己决定说不说」值钱，但它每条消息都进会话，成本按条走；我没有那个预算。

**决定**

1. 白名单内每条消息落转录（`~/.dsh/xi-qq/transcripts/*.jsonl`），**不跑模型**。
2. 她开口时，用 `agent.ctx.systemPrompt.context({ name: 'qq-scene', order: 300 })` 把最近 20 条 / 800 字挂进这一轮提示词。
3. 作用域必须是 **agent**，不是全局：全局注册会把 QQ 内容塞进网页会话的提示词。
4. 挂不上就退回 6 行正文摘要，不报错、不中断回复。
5. `scene` 三个键（`enabled` / `maxMessages` / `maxChars`）走 settings.json，2 秒热生效。

**代价**

- 每轮多 300~500 token；砍掉老摘要后基本抵平，不抵平的部分在 `qq.log` 的 `scene render ... chars=N` 里能看到。
- 依赖 DSH 内部约定：`assemble()` 传的 `scope` 就是 agent、Agent 实例带 `ctx`。这两条是读 `dsh-agent-loop` / `dsh-agent` 源码确认的，**DSH 升级要重验**。
- 转录不设上限条数，只靠 2MB 轮转（400 行）兜底。

**怎么退**

| 场景 | 动作 |
|---|---|
| 只想关掉，不撤代码 | `scene.enabled=false`，2 秒生效，回到 6 行摘要 |
| 嫌贵 | `scene.maxMessages=10`、`scene.maxChars=400` |
| 上下文注册在 DSH 升级后失效 | 看 `qq.log` 有没有 `scene: ... 拿不到 systemPrompt`，有就退回摘要，功能不崩 |
| 整段撤 | `git revert` 这个 commit，重启 DSH |

## 0003 · 2026-10-28 · 发言改成工具调用（抄 SurfCore 的第二件，0.5.0）

**背景**

0002 之后她看得见群聊近况了，但发言还是「这轮输出的文字自动转发」。那条路只有一个出口，限速、审计、引用、分条全挤在一起，也没法「想了想决定不说」。SurfCore 的 reserved2 把发言变成工具调用：文本只是思考，说了才算。

**决定**

1. 给她 5 个 `qq_*` 工具：`qq_send_message` / `qq_send_burst` / `qq_get_recent_messages` / `qq_wait_for_messages` / `qq_close_conversation`。
2. 工具挂在 **agent 作用域**（`agent.ctx.tools.register`），和 0002 同一个理由：全局注册会把 QQ 工具塞进网页会话。
3. 发送口收敛成一个 `deliver()`：每日总量、每会话冷却、每小时上限、分条都在那一处。
4. `qq_wait_for_messages` 期间来的消息由工具收下，**不另开一轮**——否则「等一会儿」会触发第二次回复。
5. 三个安全阀：注册失败退回自动转发；`tools.fallbackOnSilent` 默认 `true`（没调工具但写了字 → 补发 + 记 `silent-turn`）；设成 `false` 才是严格的「说了才算」。

**代价**

- 每轮多一份工具清单，约 300 token；省掉「不发言也要输出整段话」的部分，大致抵平。
- 模型可能学不会调工具，表现为 `qq.log` 里一堆 `silent-turn`。兜底会补发，但那等于没换——所以要看日志决定什么时候关兜底。
- 依赖 DSH 内部约定：Agent 实例带 `ctx`，`ctx.get('tools').register(朴素 definition)` 可用。这两条是读 `dsh-ops` 的 `lib/session-shells.js` 和 `lib/shells/tool.js` 确认的，**本插件真机还没验过**——挂不上会退回自动转发，不会把话吞了。

**怎么退**

| 场景 | 动作 |
|---|---|
| 只想关掉，不撤代码 | `tools.enabled=false`，2 秒生效，回到自动转发 |
| 模型总忘调工具 | `tools.fallbackOnSilent=true`（默认就是），先看 `qq.log` 的 `silent-turn` 有多少 |
| 真机挂不上（`agent.ctx.get('tools')` 拿不到） | `qq.log` 会有 `tools: ... 退回自动转发`，功能不崩，只是回到老行为 |
| 整段撤 | `git revert` 这个 commit，重启 DSH |
