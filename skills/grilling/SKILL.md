# 逼问

目标：在写第一行代码、建第一个文件之前，把设计树的每个分叉问平。问平之前不动手。

## 设计树

每个决策会分出下层的决策。根是"你到底要什么"，叶是"这个字段叫什么"。把还没定的决策画成一棵树。

## 轮次

**frontier（前沿）**＝前提已经定下来、现在就能问的问题。一次把整层前沿问完，不要挤牙膏式追问。

每轮格式：

```
❓ **Q1** <标题>：<问题，可以带选项>

➡️ <我推荐的答案>

---

❓ **Q2** ...
```

两个硬要求：

1. **每题都给推荐答案**，措辞要让「是」等于采纳我的推荐。
2. **依赖于本轮尚未回答的问题，不许放进本轮**——它属于下一轮。

## 事实归我，决策归你

- 要查的事实（文件内容、API、版本、外部资料）：我自己用工具或子 agent 查，**绝不拿"你能告诉我吗"当问题**。
- 要拍板的取舍：交给你，等你答。
- 子 agent 在跑时不要空等：只把依赖它结果的问题推到下一轮，其余这轮照问。

## 收尾

frontier 空了 ＝ 没有分叉、没有"我以为你懂"的地方。此时给一句话回放，等你确认，然后才动手。

中途发现漏问了某个已定分支的前提——停下来说明，补问，不硬着头皮往下做。

## 不做

- 不问能自己查的事实
- 不一次扔二十个问题（那样等于没问）
- 不在没确认前建文件、写代码、装东西
